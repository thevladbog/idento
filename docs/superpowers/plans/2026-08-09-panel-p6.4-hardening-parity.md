# Panel P6.4 — Mobile Hardening & Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the panel mobile-companion initiative with deterministic unit and browser acceptance: fix the confirmed 390×844 correctness/a11y gaps, add staff-only self-service navigation, make the mobile Playwright journey required, and block initial-bundle regressions while keeping Lighthouse advisory.

**Architecture:** Harden shared primitives first, then fix panel-local layout/cache/semantic behavior, then build acceptance on the corrected behavior. Role decisions use the live active-tenant membership query. Monitor attention remains cache-only. Mobile browser coverage is isolated in one 390×844 Playwright project and reuses an expanded real-backend seed. The blocking performance signal is a dependency-free byte/gzip script; Lighthouse runs three authenticated mobile collections and archives the representative report without gating `ci-success`.

**Tech Stack:** React 19, TypeScript 5.6, TanStack Router/Query, Radix Dialog, Tailwind v4, `@idento/ui`, react-i18next, Vitest + Testing Library + MSW, Playwright + Axe, Node `fs`/`zlib`, Lighthouse CI.

**Spec:** [2026-08-09-panel-p6.4-hardening-parity-design.md](../specs/2026-08-09-panel-p6.4-hardening-parity-design.md)

**Branch:** `feature/panel-p6.4-hardening-parity` in `/private/tmp/idento-panel-p6.4-hardening-parity`.

## Global Constraints

- No backend, migration, OpenAPI, generated schema, KMP, desktop, kiosk, printer, or agent change.
- `md` is the only phone/desktop cutover; reference viewport is exactly 390×844. No `/m/*`, user-agent checks, or new breakpoint.
- Panel feature code uses `@idento/ui` primitives and semantic color tokens only. Shared UI receives all user-facing copy through props.
- Every new panel string is added to both `panel/src/shared/i18n/en.json` and `ru.json` in the same commit.
- Phone-only interactive targets are at least 44×44 CSS px; body-level horizontal overflow is forbidden.
- QR bearer values stay in request/React state only. They are never persisted and never placed in DOM text or accessible names.
- Initial errors stay distinct from valid empty states. Failed background refreshes retain last-known-good data.
- Physical iOS Safari, Android Chrome, KMP QR scanning, and cellular/SSE gates remain `NOT RUN` unless separately exercised on real devices.
- After each task run its focused tests. Before phase completion run every command in Task 10, including two consecutive full panel Vitest runs.
- Commit only the files named by the task. Do not absorb unrelated worktree changes.

export async function expectTouchTargetsAtLeast44(locator: Locator) {

// panel/scripts/check-bundle.mjs
import { readFileSync, readdirSync } from "node:fs";
import { join } from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";
import { gzipSync } from "node:zlib";

export const RAW_LIMIT = 1_550_000;
export const GZIP_LIMIT = 430_000;

export function checkBundle(distDir = fileURLToPath(new URL("../dist/", import.meta.url))) {
  const assetsDir = join(distDir, "assets");
  const entries = readdirSync(assetsDir).filter((name) => /^index-[A-Za-z0-9_-]+\.js$/.test(name));
  if (entries.length !== 1) {
    throw new Error("Expected exactly one initial JS asset, found " + entries.length);
  }

  const bytes = readFileSync(join(assetsDir, entries[0]));
  const raw = bytes.byteLength;
  const gzip = gzipSync(bytes).byteLength;
  console.log("panel initial JS: raw=" + raw + " gzip=" + gzip);

  if (raw > RAW_LIMIT) throw new Error("Initial JS raw " + raw + " exceeds " + RAW_LIMIT);
  if (gzip > GZIP_LIMIT) throw new Error("Initial JS gzip " + gzip + " exceeds " + GZIP_LIMIT);
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  checkBundle();
}
