# Panel P6.4 Station Assignee Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the 390×844 real-backend mobile journey pass by containing Overview overflow, exposing the readiness scroller to keyboard users, and requiring an explicit eligible staff/manager identity before station provisioning.

**Architecture:** Keep the two layout/a11y corrections local to the workspace components that own the broken DOM. `AddStationAction` owns its live `useEventStaff(eventId)` query and selector state, filters the API's full `User[]` response to `staff | manager`, and sends only the explicitly selected user id through the existing provisioning contract. The Playwright journey selects the seeded staff member by email and verifies the request subject without exposing the returned bearer.

**Tech Stack:** React 19, TypeScript 5.6, TanStack Query, Radix Select through `@idento/ui`, react-i18next, Vitest + Testing Library + MSW, Playwright + Axe.

**Spec:** [2026-08-09-panel-p6.4-hardening-parity-design.md](../specs/2026-08-09-panel-p6.4-hardening-parity-design.md) §5.2.1.

**Branch:** `feature/panel-p6.4-hardening-parity` in `/private/tmp/idento-panel-p6.4-hardening-parity`.

## Global Constraints

- Do not change backend authorization, OpenAPI, generated schema, database migrations, KMP, desktop, kiosk, printer, or agent code.
- `md` remains the only phone/desktop cutover; the reference viewport is exactly 390×844.
- Use only `@idento/ui` primitives and semantic color tokens in panel feature code.

- Phone-only selector triggers, options, and actions are at least 44×44 CSS px; body-level horizontal overflow is forbidden.
- QR bearer values remain ephemeral React/test variables. Never log, persist, serialize into assertion output, or place them in DOM text/accessibility attributes.
